# AIComponent

AIComponent 是用于 Windows 桌面应用的 AI 对话组件，支持连接多种模型服务、流式回复、Markdown 展示，以及阅读本地文本文件和目录。应用接入业务工具后，还可以通过自然语言执行应用内操作。

## 主要功能

- **流式对话**：回复逐步显示，支持多行输入、文本复制、停止生成和清空当前对话。
- **Markdown 展示**：AI 回复支持标题、粗体、列表、代码块和表格，方便阅读技术说明和分析结果。
- **多模型配置**：在界面中添加、编辑、删除模型配置，随时切换使用。
- **独立会话**：不同 AI 配置分别保留当前会话，切换后可继续之前的话题。
- **文件阅读**：选择 TXT 或 Markdown 文件，让模型总结、解释、对比或提取信息。
- **目录阅读**：递归读取目录中的文本与代码文件，保留相对路径以区分同名文件。
- **附件管理**：发送前可逐个移除附件，本轮对话结束后自动清空已选文件列表。
- **应用内操作**：支持模型调用应用提供的业务工具，并根据执行结果继续回答。
- **配置保存**：示例程序加密保存模型配置和 API 密钥，下次启动可继续使用。

## 快速开始

### 启动示例

需要 Windows 和支持 .NET 8 WPF 的 .NET SDK。在仓库根目录执行：

```powershell
dotnet run --project ./AIComponent/AIComponent.Demo/AIComponent.Demo.csproj
```

首次运行会还原所需依赖。也可以使用支持 .NET 8 WPF 的 IDE 打开项目并启动示例。

没有已保存配置时，示例默认进入“离线演示 · 模拟播放器”。输入：

> 帮我播放一首周杰伦的歌曲

即可体验对话触发工具操作、播放器状态更新和结果回复。离线演示使用固定结果，不进行真实模型推理，也不播放真实音频。阅读文件、分析目录和自由问答需要切换到真实模型。

### 配置模型

1. 点击右上角的设置按钮。
2. 选择“添加 AI”，再选择 API 类型。
3. 填写显示名称、API 基础地址、模型 ID 和 API 密钥。
4. 根据需要选择是否启用宿主工具调用。
5. 点击“保存并使用”，返回聊天页面。
6. 在输入区的 AI 下拉框中确认当前使用的配置，开始对话。

API 地址填写服务的**基础地址**，不要填写完整的 `chat/completions` 或 `messages` 请求路径。模型 ID 需填写账户实际可用的名称，界面预填内容可以修改。Ollama 本地服务可不填密钥。

### 可选的模型服务

| API 类型 | 使用方式 |
| --- | --- |
| Agnes AI | 选择预设，填写密钥并确认模型 ID |
| Google Gemini | 使用 OpenAI 兼容接口 |
| OpenAI GPT | 填写可用的模型 ID 与密钥 |
| DeepSeek | 选择预设，填写密钥并确认模型 ID |
| Ollama（本地） | 启动本地服务，填写已安装的模型名称 |
| Anthropic Claude | 使用 Claude 原生接口 |
| 硅基流动 | 选择预设，填写密钥并确认模型 ID |
| 自定义 OpenAI 兼容服务 | 自行填写基础地址、模型 ID 和密钥 |

模型能力、上下文容量、工具支持和计费以实际服务与账户为准。不同服务的线上可用性需要使用自己的配置验证。

## 日常对话

在输入框中输入问题，点击发送按钮或按 **Enter** 发送；按 **Shift+Enter** 换行。

生成期间，发送按钮会切换为停止按钮。支持流式响应的服务会逐步显示正文；返回完整响应的服务会一次显示回答。回复较长时，可以向上滚动查看前文。

| 操作 | 效果 |
| --- | --- |
| 点击停止 | 取消当前生成 |
| 切换 AI | 切换到该配置的独立会话 |
| 点击清空 | 清空当前 AI 的会话和待发送附件 |
| 修改并保存模型配置 | 重置该配置的会话 |
| 点击设置 | 在聊天页与模型配置页之间切换 |

生成或读取附件期间，部分操作会暂时禁用，结束后恢复。

## 阅读文件与目录

### 添加文件

1. 点击输入框上方的“添加文件”。
2. 选择一个或多个 `.txt`、`.text`、`.md` 或 `.markdown` 文件。
3. 在附件列表中确认文件，点击右侧 **×** 可移除不需要的项。
4. 输入阅读要求并发送，也可以只发送附件，默认让模型阅读并概述。

例如：

> 总结这份文档的主要内容，并列出需要我确认的问题。

> 对比这两份 Markdown，说明内容上的差异。

### 添加目录

点击“添加目录”，选择要阅读的文件夹。组件会递归读取子目录中的文本文件，包括代码和没有扩展名的文本文件；列表中使用相对路径区分不同位置的同名文件。

例如：

> 阅读这些文件，解释这个项目的主要功能。

> 汇总目录中所有文档提到的待办事项。

二进制文件会跳过，目录中的文件链接和目录链接也会跳过。隐藏文本文件会包含在读取范围内。文件无法读取、编码不支持或达到限制时，状态区会提示哪些内容未添加；提示较长时可以悬停查看详情。

### 附件在对话中的行为

- 文件在选择时读取，之后修改原文件不会自动更新附件，需要重新选择。
- 发送时，所选文件的正文会提供给当前模型服务；使用远程服务时，正文会随请求发送到该服务。
- 对话进行时保留已选文件列表；本轮完成、停止或失败后，列表自动清空。
- 成功发送的文件内容保留在当前 AI 的会话中，后续可以继续追问，无需重复添加。
- 停止或失败的轮次不会保留到模型上下文；需要重试时请重新选择文件。

### 文件读取限制

| 项目 | 限制 |
| --- | --- |
| 每条消息的附件数量 | 最多 128 个文件 |
| 单个文件大小 | 最多 256 KiB |
| 每条消息的附件总大小 | 最多 2 MiB |
| 每次扫描的候选文件数量 | 最多 2000 个 |
| 支持的编码 | UTF-8，以及带 BOM 的 UTF-16 / UTF-32 |

超过限制会提示未完整读取，不会静默截断文件正文。其他文本编码请先另存为 UTF-8。模型实际可接收的上下文可能小于上述上限，文件较多时可以分批阅读。

## 使用应用工具

当应用提供业务工具且模型支持工具调用时，可以直接用自然语言提出操作要求。例如，在播放器中请求播放歌曲，或在编辑器中请求查询应用状态。可执行的操作取决于应用实际提供的工具。

在模型配置中勾选“启用宿主工具调用”后，模型会根据问题决定是否调用工具，并结合执行结果回答。

点击停止只会取消当前请求，已经执行的应用操作不会自动撤销。

## 配置与会话保存

示例程序将模型配置和 API 密钥加密保存在当前 Windows 用户下，默认位置为：

```text
%LOCALAPPDATA%/AIComponent.Demo/profiles.dat
```

该配置文件不能直接跨 Windows 用户使用。嵌入其他应用时，保存位置由应用决定。

聊天记录和附件内容仅在当前进程中保留，退出程序后不会恢复。清空当前会话不会删除已保存的模型配置。

## 当前范围

目前支持文本对话、Markdown 回复展示、文本与目录阅读，以及应用提供的工具调用。图片、音视频、PDF、Word 等非文本附件暂不支持，也尚未提供聊天记录持久化、自动上下文裁剪和工作流设计器。

开发者接入说明见 [INTEGRATION.md](INTEGRATION.md)。
